## The Retrieval Quality Problem

In Naive RAG, the system retrieves the top-K chunks and blindly passes them to the LLM. But what if those chunks are **irrelevant** to the question? The LLM will either hallucinate an answer or produce a plausible-sounding but incorrect response.

<AnalogyCard
  title="The Research Assistant Analogy"
  description="Imagine hiring a research assistant who always brings you exactly 5 articles, regardless of quality. Sometimes the articles are perfect. Sometimes they're about the wrong topic entirely. But the assistant never checks whether the articles are relevant — they just hand them over. CRAG is like teaching that assistant to READ the articles first, check if they actually answer the question, and go search the internet if the library doesn't have good sources."
/>

## Corrective RAG (CRAG)

CRAG introduces a **retrieval evaluator** that grades each retrieved document before passing it to the LLM.

```
┌────────┐    ┌──────────┐    ┌──────────────┐
│  Query │ →  │ Retrieve │ →  │   Grade      │
└────────┘    │  Top-K   │    │  Relevance   │
              └──────────┘    └──────┬───────┘
                                     │
                    ┌────────────────┬┴────────────────┐
                    │                │                  │
              ┌─────▼─────┐  ┌──────▼──────┐  ┌───────▼───────┐
              │  CORRECT   │  │  AMBIGUOUS  │  │   INCORRECT   │
              │ Use as-is  │  │ Refine query│  │ Web search    │
              └─────┬─────┘  └──────┬──────┘  └───────┬───────┘
                    │                │                  │
                    └────────────────┴─────────┬───────┘
                                               │
                                    ┌──────────▼──────────┐
                                    │    Generate Answer   │
                                    └─────────────────────┘
```

### Implementation with LangGraph

```javascript
import { StateGraph, END } from "@langchain/langgraph";
import { ChatOpenAI } from "@langchain/openai";
import { TavilySearchResults } from "@langchain/community/tools/tavily_search";

const model = new ChatOpenAI({ model: "gpt-4", temperature: 0 });
const webSearch = new TavilySearchResults({ maxResults: 3 });

// Step 1: Grade retrieved documents
async function gradeDocuments(state) {
  const { question, documents } = state;
  const relevantDocs = [];
  let needsWebSearch = false;
  
  for (const doc of documents) {
    const gradePrompt = `
      Is this document relevant to the question?
      Question: ${question}
      Document: ${doc.pageContent}
      
      Answer ONLY "yes" or "no".
    `;
    
    const grade = await model.invoke(gradePrompt);
    
    if (grade.content.trim().toLowerCase() === "yes") {
      relevantDocs.push(doc);
    }
  }
  
  // If fewer than 2 relevant docs, trigger web search
  if (relevantDocs.length < 2) {
    needsWebSearch = true;
  }
  
  return { 
    ...state, 
    documents: relevantDocs, 
    needsWebSearch 
  };
}

// Step 2: Web search fallback
async function searchWeb(state) {
  const results = await webSearch.invoke(state.question);
  const webDocs = results.map(r => ({
    pageContent: r.content,
    metadata: { source: r.url }
  }));
  
  return {
    ...state,
    documents: [...state.documents, ...webDocs]
  };
}

// Step 3: Generate answer
async function generate(state) {
  const context = state.documents.map(d => d.pageContent).join("\n\n");
  const answer = await model.invoke(`
    Answer based on this context:
    ${context}
    
    Question: ${state.question}
  `);
  
  return { ...state, answer: answer.content };
}

// Build the graph
const graph = new StateGraph({ channels: stateSchema })
  .addNode("grade", gradeDocuments)
  .addNode("web_search", searchWeb)
  .addNode("generate", generate)
  .addEdge("__start__", "grade")
  .addConditionalEdges("grade", (state) => 
    state.needsWebSearch ? "web_search" : "generate"
  )
  .addEdge("web_search", "generate")
  .addEdge("generate", END);
```

## Self-RAG: Generation with Self-Reflection

Self-RAG takes it further — after generating an answer, it **reflects on its own output** and checks:

1. **Is the answer grounded in the retrieved context?** (No hallucination)
2. **Does it actually answer the question?** (Relevance)
3. **Is it factually consistent?** (No contradictions)

```javascript
// After generating an answer, grade it
async function gradeAnswer(state) {
  const { question, answer, documents } = state;
  
  // Check 1: Is the answer grounded in the documents?
  const groundednessCheck = await model.invoke(`
    Is this answer supported by the source documents?
    
    Answer: ${answer}
    Sources: ${documents.map(d => d.pageContent).join("\n")}
    
    Respond: "grounded" or "not grounded"
  `);
  
  // Check 2: Does the answer address the question?
  const relevanceCheck = await model.invoke(`
    Does this answer actually address the question?
    
    Question: ${question}
    Answer: ${answer}
    
    Respond: "relevant" or "not relevant"
  `);
  
  const isGrounded = groundednessCheck.content.includes("grounded");
  const isRelevant = relevanceCheck.content.includes("relevant");
  
  if (!isGrounded || !isRelevant) {
    // Re-generate with a stricter prompt or try web search
    return { ...state, needsRegeneration: true };
  }
  
  return { ...state, finalAnswer: answer };
}
```

## CRAG vs Self-RAG

| Feature | CRAG | Self-RAG |
|---------|------|----------|
| **What it evaluates** | Retrieved documents (before generation) | Generated answer (after generation) |
| **Fallback strategy** | Web search for better sources | Re-generation with stricter constraints |
| **LLM calls** | 1 per document + 1 generation | 1 generation + 2-3 reflection checks |
| **Best for** | Noisy retrieval, sparse knowledge bases | High-stakes applications (medical, legal) |

> **Pro Tip:** In production, combine both — use CRAG to filter bad retrievals AND Self-RAG to verify the generated answer. This "belt and suspenders" approach dramatically reduces hallucination.
