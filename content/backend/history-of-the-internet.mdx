## 1. The Genesis

<ConceptBlock type="idea" title="Overview">
  The internet wasn't built in a day. It evolved over decades from a secret military project into the global backbone of modern society. Understanding this history helps you understand why backend systems are designed the way they are.
</ConceptBlock>

<WarningCard title="The Internet is NOT the Web">
  Just a reminder! The **Internet** is the physical network infrastructure created in the late 1960s. The **World Wide Web (WWW)** is the application layer (websites, HTTP) invented by Tim Berners-Lee in 1989 that runs *on top* of the internet.
</WarningCard>

<AnalogyCard title="Packet Switching vs Circuit Switching">
  - **Circuit Switching (Old Telephone Lines):** Like a dedicated train track. Once a train (call) is on the track, no one else can use it until the train arrives and the track is cleared. If the track breaks, communication is entirely lost.
  - **Packet Switching (The Internet):** Like sending 100 postcards through the mail system. They might take different routes, planes, and trucks, but they all eventually arrive and get reassembled. If a post office closes, the cards just route around it.
</AnalogyCard>

## 4. Node.js Implementation

To understand how the internet communicates at its most basic level, let's build the simplest possible web server using Node.js's native `http` module. This is how servers communicated before modern frameworks like Express existed!

<CodeTabs>
  <div label="server.js">
    ```javascript
    // 1. Import the native http module (built into Node.js)
    const http = require('http');

    // 2. Create the server
    const server = http.createServer((request, response) => {
      // 3. Log the incoming request to the terminal
      console.log(`Incoming request to: ${request.url}`);

      // 4. Send an HTTP 200 OK status and set the content type to plain text
      response.writeHead(200, { 'Content-Type': 'text/plain' });

      // 5. Send the actual data back to the client
      response.end('Hello from the early Internet!\n');
    });

    // 6. Tell the server to listen on port 3000
    const PORT = 3000;
    server.listen(PORT, () => {
      console.log(`🚀 Server is listening on http://localhost:${PORT}`);
    });
    ```
  </div>
</CodeTabs>

<ConceptBlock type="tip" title="What's happening here?">
  When you run this code using `node server.js`, your computer opens up **Port 3000** and listens for incoming packets. If you open your browser and go to `http://localhost:3000`, your browser sends an HTTP request packet to your Node.js server. The server reads it, logs it, and sends back a text response.
</ConceptBlock>

<WarningCard title="Don't use this in production!">
  While understanding the native `http` module is crucial for interviews, you will almost never use it directly in a production application. In modern backends, we use frameworks like **Express.js** to handle the heavy lifting of routing and security.
</WarningCard>
