## 1. The Language of the Web

<ConceptBlock type="idea" title="Overview">
  If the Internet is the physical highway, HTTP (Hypertext Transfer Protocol) is the language the cars use to communicate. It is a text-based protocol that dictates exactly how a Client must ask for data, and how a Server must reply.
</ConceptBlock>

When you type `quizkaal.in` into your browser and press Enter, your browser sends a block of text to our servers. That block of text is an HTTP Request.

<AnalogyCard title="The Core HTTP Methods (Verbs)">
  - **GET:** Like reading a book. You are retrieving information without changing it.
  - **POST:** Like writing a new chapter. You are creating a brand new resource.
  - **PUT / PATCH:** Like editing a page. You are updating an existing resource.
  - **DELETE:** Like ripping a page out of the book. You are destroying a resource.
</AnalogyCard>

<WarningCard title="Never modify data with GET">
  Using a GET request to delete or modify a user is a massive anti-pattern. GET requests should NEVER modify data on the server; they should be 'idempotent' (safe to repeat without changing state). Browsers pre-fetch GET requests, which could accidentally trigger deletions!
</WarningCard>

## 3. Status Codes

When the server replies, it includes a 3-digit number called a **Status Code**. As a Backend Engineer, you will memorize these.

- **2xx (Success):** The request was successfully received, understood, and accepted. (e.g., `200 OK`, `201 Created`).
- **3xx (Redirection):** Further action needs to be taken. (e.g., `301 Moved Permanently`).
- **4xx (Client Error):** The client messed up. You sent bad data, or you don't have permission. (e.g., `400 Bad Request`, `401 Unauthorized`, `404 Not Found`).
- **5xx (Server Error):** The server messed up. The code crashed or the database is down. (e.g., `500 Internal Server Error`).

## 4. Node.js Implementation: Methods & Status Codes

Let's build a real Express server that implements all major HTTP Methods and returns the appropriate Status Codes.

<CodeTabs>
  <div label="server.js">
    ```javascript
    const express = require('express');
    const app = express();
    
    // Middleware to parse JSON bodies
    app.use(express.json());

    // 🟢 GET: Retrieve data (200 OK)
    app.get('/api/users', (req, res) => {
      res.status(200).json({ message: "Fetched all users successfully!" });
    });

    // 🟡 POST: Create new data (201 Created)
    app.post('/api/users', (req, res) => {
      const { name } = req.body;
      if (!name) {
        // 🔴 400 Bad Request: The client forgot to send a name!
        return res.status(400).json({ error: "Name is required!" });
      }
      res.status(201).json({ message: `User ${name} created!` });
    });

    // 🟠 PUT/PATCH: Update data
    app.patch('/api/users/:id', (req, res) => {
      // Pretend we check if the user is an admin
      const isAdmin = false; 
      if (!isAdmin) {
        // 🔴 403 Forbidden: The client is authenticated, but not allowed
        return res.status(403).json({ error: "Admins only!" });
      }
      res.status(200).json({ message: "User updated!" });
    });

    // 🔴 DELETE: Destroy data
    app.delete('/api/users/:id', (req, res) => {
      const userExists = false;
      if (!userExists) {
        // 🔴 404 Not Found: The resource doesn't exist
        return res.status(404).json({ error: "User not found!" });
      }
      res.status(200).json({ message: "User deleted!" });
    });

    // 🚨 500 Internal Server Error (Something broke on the server)
    app.get('/api/crash', (req, res) => {
      res.status(500).json({ error: "Database connection failed! Our fault!" });
    });

    app.listen(3000, () => console.log('Server running on port 3000'));
    ```
  </div>
</CodeTabs>

<ConceptBlock type="tip" title="Best Practice">
  Always explicitly chain `.status(xyz)` before sending a response. If you just call `res.json()`, Express defaults to returning a `200 OK`, which is completely misleading if an error actually occurred!
</ConceptBlock>

## 5. HTTPS (The 'S' stands for Secure)

HTTP sends data in plain text. If you send your password over HTTP, anyone intercepting the packets on the Wi-Fi network can read it.

**HTTPS** encrypts the HTTP request using TLS (Transport Layer Security). To an attacker, an encrypted packet looks like random gibberish. It can only be decrypted by the final destination Server using a private SSL certificate.
