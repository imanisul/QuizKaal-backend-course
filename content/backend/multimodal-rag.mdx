## Beyond Text: The Multimodal Challenge

Standard RAG only processes **text**. But real-world documents contain:

- **Tables** with financial data, specs, or comparisons
- **Charts and graphs** showing trends or distributions
- **Diagrams** illustrating architectures or workflows
- **Images** with embedded text (screenshots, scanned documents)
- **Code blocks** with syntax that gets mangled by text extractors

When you naively extract text from a PDF, you lose most of this information.

## Strategies for Multimodal Documents

### Strategy 1: Text Extraction with Summarization

Extract text and use an LLM to generate text descriptions of visual elements.

```javascript
import { PDFLoader } from "langchain/document_loaders/fs/pdf";
import { ChatOpenAI } from "@langchain/openai";

// Load PDF text
const loader = new PDFLoader("./annual-report.pdf", {
  splitPages: true,
});
const pages = await loader.load();

// For pages with tables/charts, use GPT-4V to describe them
const visionModel = new ChatOpenAI({ 
  model: "gpt-4o",
  maxTokens: 1000 
});

async function describeImage(imageBase64) {
  const response = await visionModel.invoke([
    {
      role: "user",
      content: [
        { type: "text", text: "Describe this image in detail. Include all data from tables and charts." },
        { type: "image_url", image_url: { url: `data:image/png;base64,${imageBase64}` } }
      ]
    }
  ]);
  return response.content;
}
```

### Strategy 2: Multi-Vector Retrieval

Store **both** the raw image/table and a text summary. Retrieve using the text summary but pass the original image to the LLM.

```javascript
import { MultiVectorRetriever } from "langchain/retrievers/multi_vector";
import { InMemoryStore } from "langchain/storage/in_memory";

const docStore = new InMemoryStore();
const vectorStore = await Chroma.fromDocuments([], embeddings);

// For each page with images:
// 1. Generate a text summary of the image
// 2. Store the summary in the vector store (for retrieval)
// 3. Store the original image in the doc store (for generation)

const retriever = new MultiVectorRetriever({
  vectorstore: vectorStore,
  docstore: docStore,
  idKey: "doc_id",
});

// At query time:
// - Searches SUMMARIES to find relevant content
// - Returns ORIGINAL documents (including images) for the LLM
```

### Strategy 3: Direct Vision Model Queries

For simple use cases, skip traditional RAG entirely and send document images directly to a vision-capable LLM.

```javascript
import * as fs from "fs";

// Convert PDF pages to images
// (using pdf-poppler, sharp, or similar libraries)
const pageImages = await convertPdfToImages("./report.pdf");

// Ask questions directly about the images
const answer = await visionModel.invoke([
  {
    role: "user",
    content: [
      { type: "text", text: "What was the revenue growth rate shown in Q3?" },
      ...pageImages.map(img => ({
        type: "image_url",
        image_url: { url: `data:image/png;base64,${img}` }
      }))
    ]
  }
]);
```

## Handling Tables

Tables are notoriously difficult for text extractors. Here's how to handle them properly:

```javascript
// BAD: Naive text extraction of a table
// "Product Revenue Growth | Laptops $2.3M 15% | Phones $5.1M 23%"
// The LLM can't parse this mess

// GOOD: Use a table-aware parser
import { UnstructuredLoader } from "langchain/document_loaders/fs/unstructured";

const loader = new UnstructuredLoader("./report.pdf", {
  strategy: "hi_res",            // Use OCR + layout detection
  includePageBreaks: true,
  chunkingStrategy: "by_title",  // Split by section headers
});

// This preserves table structure as markdown:
// | Product | Revenue | Growth |
// |---------|---------|--------|
// | Laptops | $2.3M   | 15%    |
// | Phones  | $5.1M   | 23%    |
```

## When to Use Each Strategy

| Strategy | Best For | Limitation |
|----------|----------|-----------|
| **Text + Summaries** | PDFs with occasional images | Summary may miss visual details |
| **Multi-Vector** | Diagram-heavy technical docs | Complex to set up |
| **Direct Vision** | Small document sets (< 20 pages) | Expensive, slow, can't scale |
| **Table-Aware Parsing** | Financial reports, specs | Requires specialized parsers |
