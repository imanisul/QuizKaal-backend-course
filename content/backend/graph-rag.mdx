## Why Knowledge Graphs?

Naive RAG treats documents as **isolated chunks**. It cannot answer questions that require understanding **relationships between entities**.

| Query | Naive RAG | GraphRAG |
|-------|-----------|----------|
| "Who reports to the VP of Engineering?" | Retrieves random chunks mentioning "VP" | Traverses the org chart graph: VP → DirectReports |
| "What products use the same database as Service X?" | Might find irrelevant mentions of databases | Follows edges: ServiceX → uses → PostgresDB ← uses → ServiceY |
| "How are Alice and Bob connected?" | Finds chunks about Alice OR Bob separately | Traverses: Alice → manages → TeamAlpha ← memberOf → Bob |

## What is a Knowledge Graph?

A Knowledge Graph stores data as **nodes** (entities) and **edges** (relationships):

```
┌──────────┐    manages    ┌──────────┐
│  Alice   │──────────────▶│  Team X  │
│ (Person) │               │  (Team)  │
└──────────┘               └──────────┘
      │                          │
      │ works_at            builds
      ▼                          ▼
┌──────────┐               ┌──────────┐
│  Acme    │               │ Product  │
│(Company) │               │   API    │
└──────────┘               └──────────┘
```

## Neo4j: The Graph Database

Neo4j stores data natively as a graph and queries it using **Cypher** — a pattern-matching query language.

```cypher
// Create nodes and relationships
CREATE (alice:Person {name: "Alice", role: "Engineering Manager"})
CREATE (bob:Person {name: "Bob", role: "Senior Engineer"})
CREATE (teamX:Team {name: "Platform Team"})

CREATE (alice)-[:MANAGES]->(teamX)
CREATE (bob)-[:MEMBER_OF]->(teamX)
CREATE (teamX)-[:BUILDS]->(api:Service {name: "Payment API"})

// Query: Who is on the team that builds the Payment API?
MATCH (person:Person)-[:MEMBER_OF]->(team:Team)-[:BUILDS]->(s:Service)
WHERE s.name = "Payment API"
RETURN person.name, person.role
```

## Building a GraphRAG Pipeline

### Step 1: Extract Entities from Documents

Use an LLM to extract entities and relationships from unstructured text:

```javascript
import { ChatOpenAI } from "@langchain/openai";

const extractionPrompt = `
Extract all entities and relationships from this text.

Return JSON:
{
  "entities": [
    { "name": "...", "type": "Person|Company|Product|Technology" }
  ],
  "relationships": [
    { "source": "...", "target": "...", "relation": "..." }
  ]
}

Text: {text}
`;

const model = new ChatOpenAI({ model: "gpt-4", temperature: 0 });
const result = await model.invoke(extractionPrompt.replace("{text}", document));
const graph = JSON.parse(result.content);
```

### Step 2: Store in Neo4j

```javascript
import neo4j from "neo4j-driver";

const driver = neo4j.driver(
  "bolt://localhost:7687",
  neo4j.auth.basic("neo4j", "password")
);

const session = driver.session();

// Insert extracted entities
for (const entity of graph.entities) {
  await session.run(
    `MERGE (e:${entity.type} {name: $name})`,
    { name: entity.name }
  );
}

// Insert relationships
for (const rel of graph.relationships) {
  await session.run(
    `MATCH (a {name: $source}), (b {name: $target})
     MERGE (a)-[:${rel.relation}]->(b)`,
    { source: rel.source, target: rel.target }
  );
}
```

### Step 3: Query with Graph Traversal + LLM

```javascript
async function graphRAG(question) {
  // 1. Use LLM to generate a Cypher query
  const cypherPrompt = `
    Given this question, write a Neo4j Cypher query to find the answer.
    Schema: (Person)-[:MANAGES]->(Team)-[:BUILDS]->(Service)
    Question: ${question}
  `;
  
  const cypher = await model.invoke(cypherPrompt);
  
  // 2. Execute the Cypher query
  const result = await session.run(cypher.content);
  
  // 3. Pass the graph results as context to the LLM
  const answerPrompt = `
    Based on this graph data, answer the question.
    Graph data: ${JSON.stringify(result.records)}
    Question: ${question}
  `;
  
  return await model.invoke(answerPrompt);
}

const answer = await graphRAG("Which teams use PostgreSQL?");
```

## GraphRAG vs Naive RAG

| Feature | Naive RAG | GraphRAG |
|---------|-----------|----------|
| **Data Structure** | Flat chunks in a vector store | Entities + relationships in a graph |
| **Query Type** | Single-hop semantic similarity | Multi-hop relationship traversal |
| **Best For** | "What is X?" questions | "How is X related to Y?" questions |
| **Setup Complexity** | Low | High (requires entity extraction + graph DB) |
| **Maintenance** | Re-embed on doc changes | Re-extract entities on doc changes |
