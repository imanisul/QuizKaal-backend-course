## The Problem with Pure Vector Search

Vector search is powerful for semantic matching, but it has blind spots:

| Query | Vector Search Issue |
|-------|-------------------|
| "error code E-4012" | Semantic search doesn't understand error codes as exact identifiers |
| "John Smith's account" | Names don't have semantic meaning — "John Smith" isn't semantically closer to his account than "Jane Doe" |
| "version 3.2.1 changelog" | Version numbers need exact matching, not semantic similarity |

**Keyword search** (like BM25/Elasticsearch) excels at these cases but fails at semantic understanding. The solution? **Combine both.**

## What is Hybrid Search?

Hybrid Search runs **both** keyword search and vector search, then **merges** the results using a fusion algorithm.


## BM25: The Keyword Search Algorithm

BM25 (Best Matching 25) is the industry-standard keyword search algorithm used by Elasticsearch and Solr. It scores documents based on:

- **Term Frequency (TF):** How many times the query term appears in the document
- **Inverse Document Frequency (IDF):** How rare the term is across all documents
- **Document Length:** Longer documents are penalized slightly

```javascript
// Simplified BM25 scoring
function bm25Score(term, document, corpus) {
  const k1 = 1.5;  // term frequency saturation
  const b = 0.75;   // length normalization
  
  const tf = termFrequency(term, document);
  const idf = Math.log(
    (corpus.length - documentsContaining(term) + 0.5) /
    (documentsContaining(term) + 0.5)
  );
  const avgDl = averageDocumentLength(corpus);
  const dl = document.length;
  
  return idf * (tf * (k1 + 1)) / 
         (tf + k1 * (1 - b + b * (dl / avgDl)));
}
```

## Reciprocal Rank Fusion (RRF)

RRF is the simplest and most effective way to merge two ranked lists:

```javascript
function reciprocalRankFusion(results1, results2, k = 60) {
  const scores = {};
  
  // Score each document by its rank in each list
  results1.forEach((doc, rank) => {
    scores[doc.id] = (scores[doc.id] || 0) + 1 / (k + rank + 1);
  });
  
  results2.forEach((doc, rank) => {
    scores[doc.id] = (scores[doc.id] || 0) + 1 / (k + rank + 1);
  });
  
  // Sort by combined score
  return Object.entries(scores)
    .sort((a, b) => b[1] - a[1])
    .map(([id, score]) => ({ id, score }));
}
```

## Cross-Encoder Re-Ranking

After fusion, the top results are **re-ranked** using a cross-encoder model. Unlike embeddings (which encode query and document separately), a cross-encoder takes the **query + document pair together** and produces a relevance score.

```javascript
import { CohereRerank } from "@langchain/cohere";

// After initial retrieval (BM25 + vector)
const initialResults = await hybridSearch(query, 20); // Get top 20

// Re-rank with a cross-encoder
const reranker = new CohereRerank({
  model: "rerank-english-v3.0",
  topN: 5, // Return only the top 5 after re-ranking
});

const rerankedResults = await reranker.compressDocuments(
  initialResults,
  query
);

// rerankedResults are now ordered by ACTUAL relevance, not just similarity
```

### Why Re-Ranking Works Better

| Stage | Speed | Accuracy | Method |
|-------|-------|----------|--------|
| **BM25** | Very fast | Good for keywords | Inverted index |
| **Vector Search** | Fast | Good for meaning | ANN (approximate nearest neighbors) |
| **Cross-Encoder** | Slow | Excellent | Full attention over query+document |

The pipeline uses fast methods first (to narrow 100K docs → 20) and then the expensive cross-encoder (to rank 20 → 5).
