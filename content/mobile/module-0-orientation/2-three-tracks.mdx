# The Three Tracks

In this course, we teach three distinct paths to mobile engineering. You don't have to learn all three simultaneously, but understanding the differences makes you a Senior Mobile Engineer.

## 1. Introduction

When building a mobile application, companies must decide their technical stack. Do they write code twice (once for iOS, once for Android) using Native tools? Or do they write it once using Cross-Platform frameworks like React Native or Flutter? 

## 2. Why this concept exists

Cross-platform frameworks save time and money, but Native development offers maximum performance and immediate access to new OS features. Understanding the trade-offs is a critical architecture decision.

## 4. Internal Working: Rendering

- **Native (Kotlin/Swift):** Directly creates OS-level buttons (`android.widget.Button` or `UIButton`).
- **React Native:** JavaScript tells the OS to create native buttons over a bridge. The UI *looks* 100% native.
- **Flutter:** Does *not* use native buttons. It draws every pixel on a blank canvas (like a video game engine).

## 7. Real-world Examples

- **Native:** Lyft, WhatsApp. They require extreme optimization and deep hardware integration.
- **React Native:** Instagram, Discord, Coinbase. They have massive web engineering teams that they transitioned to mobile.
- **Flutter:** Google Pay, Alibaba, BMW. They wanted pixel-perfect custom UI designs that look identical on both platforms.

## 8. Best Practices

- **Specialize first:** Pick a primary track. Do not try to learn React Native, Flutter, and Android perfectly at the exact same time. 
- **Leverage Web Skills:** If you know React/Web, start with **React Native**.
- **Leverage OOP Skills:** If you love Object-Oriented Programming (Java/C#), start with **Android (Kotlin)** or **Flutter (Dart)**.

## 9. Common Mistakes

- **Assuming 100% cross-platform:** Believing cross-platform means you don't need to know native code. *Eventually, you will always have to write native code for complex features.*
- **Premature Optimization:** Starting a massive production app without understanding the limitations of the chosen framework.

## 12. Summary

There is no "best" framework. Each tool has trade-offs regarding development speed, performance, and hardware access. By the end of this course, you will be able to confidently build apps in any of them.
