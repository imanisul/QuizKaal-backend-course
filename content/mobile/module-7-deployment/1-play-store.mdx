# Play Store & CI/CD

Building the app is only 50% of the job. Getting it onto 2 billion devices worldwide is the other 50%.

## 1. Introduction

Unlike the web where you just upload files to a server and users refresh their browser, mobile apps must be cryptographically signed, reviewed by human moderators at Apple and Google, and distributed through centralized App Stores. 

## 2. Why this concept exists

The App Store and Play Store exist to protect users from malware. Before your app is allowed on a user's phone, it must be vetted. This creates a massive bottleneck for developers—you cannot push a "quick bug fix" in 5 minutes. It might take 2 days to get approved.

## 4. Internal Working: Cryptographic Signing

You cannot upload raw source code to the App Store.
- **Android:** You generate a Keystore file (`.jks`). You use this file to sign an Android App Bundle (`.aab`). If you lose this Keystore file, you can **never** update your app again. Google will force you to create a brand new app.
- **iOS:** You generate Provisioning Profiles and Certificates from the Apple Developer Portal. You use Xcode to build an `.ipa` archive.

## 7. Real-world Examples

- **Over-the-Air (OTA) Updates:** Because App Store reviews take days, React Native apps often use Microsoft CodePush. This allows developers to push JavaScript updates directly to the user's phone, bypassing the App Store review entirely (legal, as long as it doesn't change the core purpose of the app).

## 8. Best Practices

- **Automate everything:** Human error during the release process causes production crashes. Use GitHub Actions and Fastlane.
- **Never commit your Keystore:** Put your `.jks` file and passwords in an encrypted environment variable or a private vault. Never commit them to a public GitHub repository.

## 9. Common Mistakes

- **Forgetting to increment the version code:** The Play Store and App Store will reject your upload if the internal `versionCode` or `buildNumber` is the exact same as a previous upload.
- **Losing the Android Keystore password:** It is unrecoverable.
