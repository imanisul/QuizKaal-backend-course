# Screens, Stacks, and Tabs

In mobile engineering, managing how users move between different views is far more complex than standard web navigation.

## 1. Introduction

On the web, clicking a link changes the URL and completely unloads the previous page. In a mobile app, moving to a new screen often involves "pushing" the new screen on top of the old one, keeping the old screen alive in memory underneath. 

## 2. Why this concept exists

Mobile phones have hardware "Back" buttons (or back swipe gestures). If mobile navigation worked like the web, swiping back would force the phone to re-download and re-render the entire previous screen. By keeping old screens alive in memory (a Stack), swiping back is instantaneous.

## 4. Internal Working: Stacks vs Tabs

There are two primary paradigms in mobile navigation:
1. **Stacks (Stack Navigator):** Pushing and popping screens. Used for deep-diving into content (e.g. Feed -> Post -> User Profile).
2. **Tabs (Tab Navigator):** Flat hierarchy. Used for switching between completely different sections of the app (e.g. Home, Search, Profile). Tabs do *not* pile on top of each other.

## 7. Real-world Examples

- **Settings Menus:** When you go to `Settings -> Display -> Brightness`, you are pushing 3 screens onto a stack. Hitting back pops them off one by one.
- **Instagram:** The bottom icons (Home, Search, Reels, Profile) are a Tab Navigator. But if you tap a Reel, it pushes a new screen onto the Stack *inside* the Reels Tab.

## 8. Best Practices

- **Don't push the same screen twice:** If you push "Profile", then push "Profile" again, the user will have to hit back twice to escape. 
- **Clear the stack on Logout:** When a user logs out, you must clear the entire navigation stack so they cannot hit the back button and return to the authenticated area.

## 9. Common Mistakes

- **Memory Leaks:** Pushing 100 screens onto a stack without ever popping them. The OS will run out of memory and crash your app.
- **Passing massive data objects:** Do not pass massive JSON objects through navigation parameters. Pass an ID, and let the new screen fetch the data.
