# Rendering Pipelines (16ms Rule)

Why do some mobile apps feel buttery smooth while others stutter and lag when you scroll? The answer lies in the 16-millisecond rule.

## 1. Introduction

Mobile phones have standard refresh rates of 60 Hertz (60 frames per second). Some modern phones (like the iPhone Pro or Pixel Pro) have 120Hz screens. To maintain 60fps, your app must calculate layout, execute javascript, and draw the pixels to the screen in exactly **16.67 milliseconds** (or 8ms for 120Hz).

## 2. Why this concept exists

If your code takes 25ms to execute, the phone will miss the 16.67ms deadline. The screen will display the *old* frame twice. This is called a "dropped frame" or "jank". If you drop multiple frames in a row while the user is scrolling, the app feels cheap and broken.

## 4. Internal Working: The Threads

- **UI Thread (Main Thread):** The only thread allowed to touch the screen. It must remain perfectly idle, waiting to draw 60 times a second.
- **Background Threads:** Used for network requests, database parsing, and heavy math.
- **The JS Thread (React Native only):** React Native runs your business logic on a separate JS thread. It communicates with the UI thread asynchronously.

## 7. Real-world Examples

- **Twitter Feed:** Twitter uses aggressive virtualization. As you scroll down, the tweets that go off the top of the screen are actually destroyed and removed from memory. When you scroll back up, they are recreated. This keeps memory usage low and frame rates at 60fps.

## 8. Best Practices

- **Avoid heavy computations in `render()`:** Never map over a 5000-item array inside your render function. Memoize it.
- **Optimize Images:** Do not load a 4K 10MB image into a 50x50 pixel avatar circle. Use a CDN to resize the image to 50x50 *before* sending it to the phone.

## 9. Common Mistakes

- **React Native Bridge Traffic:** Sending a massive base64 encoded string across the React Native JS Bridge. The bridge gets blocked, the JS thread locks up, and the app drops frames.
- **Animations on the JS Thread:** Always use `useNativeDriver: true` (or Reanimated) to run animations directly on the UI thread, bypassing JS entirely.

## 12. Summary

Performance is a feature. Users might not know what a "dropped frame" is, but they know when an app feels slow. By understanding the 16ms rule, virtualization, and threading, you can build apps that feel incredibly premium.
