# Specialization & Interview Prep

You understand the fundamentals. Now, what does it take to get hired as a Senior Mobile Engineer?

## 1. Introduction

The mobile engineering landscape is vast. No one knows everything. Senior engineers specialize in specific domains while maintaining a broad understanding of the rest of the stack.

## 2. Why this concept exists

Companies do not hire "generic programmers" for senior roles. They hire experts to solve specific problems. A FinTech app needs a Security specialist. A 3D game needs a Graphics specialist.

## 4. Internal Working: Specializations

Here are common specializations in Mobile Engineering:
- **UI/UX & Animations:** Creating complex, 120fps gesture-driven animations (e.g., Tinder swipe, Snapchat camera).
- **Core Architecture & CI/CD:** Designing the multi-module code structure and managing the Fastlane/Jenkins deployment pipelines.
- **Offline & Sync:** Managing complex local databases (SQLite/Realm) and syncing massive amounts of data in the background (e.g., Spotify, Netflix).

## 7. Real-world Examples

- In massive companies like Facebook or Uber, there are engineers whose *entire job* is simply reducing the app startup time by 0.2 seconds. They don't build UI; they profile C++ memory heaps all day.

## 8. Best Practices for Interviews

- **Think out loud:** When given a system design problem (e.g. "Design WhatsApp"), talk through your decisions. "I would choose a WebSocket for real-time messaging, and SQLite for local caching."
- **Mention edge cases:** A junior engineer says, "I will fetch the data." A senior engineer says, "I will fetch the data, but if the user goes through a tunnel and the network drops, I will catch the timeout and show a cached UI."

## 9. Common Mistakes

- **Trying to learn everything:** You do not need to be an expert in React Native, Flutter, Kotlin, Swift, and C++. Pick one track and master it deeply.
- **Ignoring the backend:** You must understand how REST APIs and databases work to be an effective mobile engineer.

## 10. Interview Questions

<InterviewQuestion 
  question="Design Instagram's offline feed architecture."
  answer="When the app is online, fetch the latest JSON from the API and instantly save it to a local SQLite database using an ORM like Room or WatermelonDB. Bind the UI solely to the local database via reactive observers. When the app goes offline, the UI simply continues to read from the local database, completely unaware that the network died."
  bestPractice="This is called the 'Offline-First' pattern. The network syncs the database, and the database drives the UI."
/>

<InterviewQuestion 
  question="How do you handle a scenario where an API request fails?"
  answer="First, wrap the fetch in a try/catch. If it catches an error, check the error type. If it's a 401 Unauthorized, trigger a token refresh. If it's a 500 Server Error or Network Timeout, update the local state to show a friendly Error UI component to the user with a 'Tap to Retry' button, rather than failing silently or crashing."
/>

<InterviewQuestion
