# Language Primers (JS, Dart, Kotlin)

Before we start building UI layouts, we must establish a strong foundation in the primary languages powering mobile engineering.

## 1. Introduction

Each mobile track utilizes a specific programming language. React Native uses JavaScript (or TypeScript), Flutter uses Dart, and Native Android uses Kotlin (or Java). Modern languages share many paradigms, making it surprisingly easy to learn the others once you master one.

## 2. Why this concept exists

Languages are just tools to execute logic. However, features like asynchronous programming, static typing, and null safety drastically affect how stable your mobile application will be in production.

## 4. Internal Working: Async Operations

Mobile apps are inherently asynchronous. While rendering the UI on the Main Thread (Thread 1), you might need to fetch data from the internet. If you do this on the Main Thread, the app will freeze and crash.

- When you open the **Instagram** app, the UI immediately loads from the local cache while an `async` function silently fetches new posts in the background.

## 8. Best Practices

- **Always Handle Errors:** Always use `try/catch` when dealing with asynchronous code. If a network request fails and is unhandled, your app will crash.
- **Type Safety:** Prefer TypeScript over JavaScript in React Native. Catching type errors during compilation saves hours of mobile debugging.
- **Null Safety:** Leverage Kotlin and Dart's strict null-safety to avoid the dreaded Null Pointer Exceptions at runtime.

## 9. Common Mistakes

- **Blocking the Main Thread:** Running heavy mathematical computations (like image processing) directly on the UI thread without offloading it to a background worker.
- **Ignoring API Timeouts:** Failing to handle cases where the server takes longer than expected to respond, leaving the user staring at an infinite loading spinner.

## 12. Summary

Modern mobile languages are powerful and share many concepts like `async/await` and null safety. The core engineering principle remains the same: Keep heavy work off the Main UI Thread to ensure smooth 60fps scrolling.
