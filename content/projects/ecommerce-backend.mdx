## Project Overview

In this project, we'll architect the backend for a high-traffic e-commerce store. We are moving past CRUD and dealing with real-world problems: what happens if two users buy the last item at the exact same time? How do we ensure we don't ship items if the payment fails?

### Core Requirements

1. **Product Catalog:** List products, categories, and inventory counts.
2. **Cart & Checkout:** Calculate totals, apply taxes, and process Stripe payments.
3. **Inventory Management:** Safely deduct stock (handling race conditions).
4. **Order Management:** Track order states (Pending → Paid → Shipped).

## Architecture & Tech Stack

- **Node.js + Express** (API Layer)
- **PostgreSQL** (Relational data + ACID transactions)
- **Prisma** (ORM)
- **Stripe** (Payment Gateway)
- **Redis** (Shopping cart caching - optional)

## 1. Database Schema (Prisma)

A robust e-commerce schema requires careful relationship mapping. 

```prisma
model User {
  id        String   @id @default(uuid())
  email     String   @unique
  password  String
  orders    Order[]
}

model Product {
  id          String   @id @default(uuid())
  name        String
  price       Int      // Store prices in CENTS to avoid floating point math
  inventory   Int
  orderItems  OrderItem[]
}

model Order {
  id            String   @id @default(uuid())
  userId        String
  user          User     @relation(fields: [userId], references: [id])
  status        OrderStatus @default(PENDING)
  totalAmount   Int
  stripeId      String?
  items         OrderItem[]
  createdAt     DateTime @default(now())
}

model OrderItem {
  id        String   @id @default(uuid())
  orderId   String
  order     Order    @relation(fields: [orderId], references: [id])
  productId String
  product   Product  @relation(fields: [productId], references: [id])
  quantity  Int
  priceAtBuy Int     // Historical price (products change price later!)
}

enum OrderStatus {
  PENDING
  PAID
  FAILED
  SHIPPED
}
```

> **Pro Tip:** Notice `priceAtBuy` in the `OrderItem` table. If you just link to the Product table's price, past orders will change totals when you update a product's price next year! Always copy the price at the time of purchase.

## 2. The Checkout Transaction

This is the most critical part of the system. We must use a **Database Transaction**. If the payment succeeds but the database crashes before saving the order, we have a major problem.

```javascript
// POST /api/checkout
app.post("/checkout", async (req, res) => {
  const { userId, cartItems } = req.body;
  
  try {
    // 1. Start a database transaction
    const order = await prisma.$transaction(async (tx) => {
      
      let totalAmount = 0;
      const orderItemsData = [];
      
      // 2. Validate inventory & calculate total
      for (const item of cartItems) {
        const product = await tx.product.findUnique({ 
          where: { id: item.productId } 
        });
        
        if (product.inventory < item.quantity) {
          throw new Error(`Not enough stock for ${product.name}`);
        }
        
        totalAmount += product.price * item.quantity;
        orderItemsData.push({
          productId: product.id,
          quantity: item.quantity,
          priceAtBuy: product.price
        });
        
        // 3. Deduct inventory safely
        await tx.product.update({
          where: { id: product.id },
          data: { inventory: { decrement: item.quantity } }
        });
      }
      
      // 4. Create the pending order
      return await tx.order.create({
        data: {
          userId,
          totalAmount,
          status: "PENDING",
          items: { create: orderItemsData }
        }
      });
    });
    
    // 5. Create Stripe Payment Intent
    const paymentIntent = await stripe.paymentIntents.create({
      amount: order.totalAmount,
      currency: "usd",
      metadata: { orderId: order.id }
    });
    
    res.json({ clientSecret: paymentIntent.client_secret, orderId: order.id });
    
  } catch (error) {
    res.status(400).json({ error: error.message });
  }
});
```

### Why use `$transaction`?
If `throw new Error("Not enough stock")` runs on the 3rd item in the cart, the transaction rolls back. The inventory deducted for the 1st and 2nd items is magically restored. This prevents inconsistent database states.

## 3. Stripe Webhooks

The client pays Stripe directly. Stripe then sends our server an HTTP request (a Webhook) telling us the payment succeeded.

```javascript
// POST /api/webhooks/stripe
app.post("/webhooks/stripe", express.raw({type: 'application/json'}), async (req, res) => {
  const signature = req.headers['stripe-signature'];
  let event;
  
  try {
    // Verify this actually came from Stripe
    event = stripe.webhooks.constructEvent(
      req.body, 
      signature, 
      process.env.STRIPE_WEBHOOK_SECRET
    );
  } catch (err) {
    return res.status(400).send(`Webhook Error: ${err.message}`);
  }

  // Handle the event
  if (event.type === 'payment_intent.succeeded') {
    const paymentIntent = event.data.object;
    const orderId = paymentIntent.metadata.orderId;
    
    // Mark order as PAID
    await prisma.order.update({
      where: { id: orderId },
      data: { status: "PAID", stripeId: paymentIntent.id }
    });
    
    // (Optional) Send confirmation email here
  }
  
  if (event.type === 'payment_intent.payment_failed') {
    // Restore inventory if payment failed!
    const orderId = event.data.object.metadata.orderId;
    await restoreInventory(orderId);
  }

  res.send();
});
```
