## Project Overview

We're building a Discord-style chat application. Users can join rooms, send messages instantly, and see who is currently online.

### Why not HTTP?

Standard HTTP is **stateless and unidirectional**. The client requests data, the server replies, and the connection closes. If Bob sends a message, the server has no way to "push" it to Alice unless Alice constantly asks the server, "Do I have new messages?" (Long Polling). 

**WebSockets** provide a persistent, bi-directional connection. The server can push data to the client at any time.

## 1. Basic WebSocket Setup (Socket.io)

Socket.io is a popular library that wraps standard WebSockets and provides auto-reconnection, rooms, and broadcasting.

```javascript
// server.js
const express = require('express');
const http = require('http');
const { Server } = require('socket.io');

const app = express();
const server = http.createServer(app);
const io = new Server(server, {
  cors: { origin: "http://localhost:3000" }
});

// Middleware for authentication
io.use((socket, next) => {
  const token = socket.handshake.auth.token;
  const user = verifyJwt(token);
  if (!user) return next(new Error("unauthorized"));
  
  socket.user = user; // Attach user data to the socket connection
  next();
});

io.on('connection', (socket) => {
  console.log(`User connected: ${socket.user.name}`);
  
  // Join a specific chat room
  socket.on('join_room', (roomId) => {
    socket.join(roomId);
    console.log(`${socket.user.name} joined room ${roomId}`);
  });
  
  // Listen for incoming messages
  socket.on('send_message', async (data) => {
    const { roomId, content } = data;
    
    const message = {
      id: generateId(),
      content,
      senderId: socket.user.id,
      senderName: socket.user.name,
      timestamp: new Date()
    };
    
    // 1. Save to database
    await db.message.create({ data: message });
    
    // 2. Broadcast to everyone else in the room
    socket.to(roomId).emit('receive_message', message);
  });
  
  socket.on('disconnect', () => {
    console.log(`User disconnected: ${socket.user.name}`);
  });
});

server.listen(4000, () => console.log('Listening on port 4000'));
```

## 2. The Scaling Problem

The code above works perfectly... until you have 10,000 concurrent users. A single Node.js server can only handle so many connections before running out of memory.

So, you deploy **Server A** and **Server B** behind a Load Balancer.

**The Problem:**
1. Alice connects to Server A.
2. Bob connects to Server B.
3. They are in the same chat room.
4. Alice sends a message to Server A.
5. Server A broadcasts the message to everyone connected to Server A.
6. **Bob never gets the message** because he is on Server B!

## 3. The Solution: Redis Pub/Sub

To solve this, we use Redis as a central message broker. When Server A receives a message, it publishes it to Redis. Server B is subscribed to Redis, receives the message, and forwards it to Bob.

Socket.io has a built-in Redis Adapter for this exact architecture.

```javascript
// Scaled Server setup with Redis
const { createAdapter } = require("@socket.io/redis-adapter");
const { createClient } = require("redis");

const pubClient = createClient({ url: process.env.REDIS_URL });
const subClient = pubClient.duplicate();

Promise.all([pubClient.connect(), subClient.connect()]).then(() => {
  // Tell Socket.io to use Redis for routing messages between servers
  io.adapter(createAdapter(pubClient, subClient));
  server.listen(4000);
});
```

With just those 5 lines of code, Alice on Server A can now seamlessly message Bob on Server B. The architecture looks like this:

```
[Alice] <──ws──> [Server A] ──pub──┐
                                   ▼
                             [Redis Broker]
                                   │
[Bob]   <──ws──> [Server B] ◄──sub─┘
```

## 4. Presence (Who is online?)

Tracking online status across multiple servers is tricky. We can use Redis Sets to store active users.

```javascript
// On connect
io.on('connection', async (socket) => {
  const userId = socket.user.id;
  
  // Add user to a Redis Set
  await redis.sAdd("online_users", userId);
  
  // Notify friends
  io.emit("user_status_change", { userId, status: "online" });
  
  socket.on('disconnect', async () => {
    // Remove from Redis Set
    await redis.sRem("online_users", userId);
    io.emit("user_status_change", { userId, status: "offline" });
  });
});
```

> **Pro Tip:** What if the server crashes? The `disconnect` event won't fire, and the user will be stuck as "online" forever in Redis. To fix this, use Redis Keyspace Notifications or heartbeats with expiring keys (TTL).
