## What are Embeddings?

An embedding is a **numerical representation of meaning**. It converts text (or images, audio, etc.) into a vector — an array of floating-point numbers — where **similar meanings are close together** in vector space.

<AnalogyCard
  title="The Map Analogy"
  description="Imagine a map where cities are placed by cultural similarity instead of geography. Tokyo and Seoul would be close together. Paris and Rome would be close together. But Tokyo and Paris would be far apart. An embedding model creates this kind of 'meaning map' for text — sentences with similar meanings get placed close together in a high-dimensional space."
/>

```javascript
import { OpenAIEmbeddings } from "@langchain/openai";

const embeddings = new OpenAIEmbeddings({ model: "text-embedding-3-small" });

const vectors = await embeddings.embedDocuments([
  "How do I reset my password?",
  "I forgot my login credentials",
  "What is quantum physics?",
]);

// vectors[0] and vectors[1] will be CLOSE (similar meaning)
// vectors[0] and vectors[2] will be FAR APART (different meaning)

// Each vector is an array of 1536 numbers:
// [0.0123, -0.0456, 0.0789, ..., -0.0321]
```

## Why Not Just Use SQL?

Traditional databases search by **exact matching** (WHERE name = 'Alice'). But AI applications need **semantic search** — finding results based on meaning, not exact keywords.

| Query | SQL Result | Vector DB Result |
|-------|-----------|-----------------|
| "headache medicine" | Only finds rows containing "headache medicine" | Also finds "aspirin", "ibuprofen", "pain relief" |
| "affordable housing" | Only exact matches | Also finds "low-cost apartments", "budget real estate" |

## How Vector Databases Work

1. **Embed:** Convert your documents into vectors using an embedding model
2. **Store:** Save the vectors (and original text) in a vector database
3. **Query:** Convert the user's question into a vector
4. **Search:** Find the most similar vectors using distance metrics (cosine similarity, Euclidean distance)
5. **Return:** Return the original documents associated with those vectors

```javascript
import { Chroma } from "@langchain/community/vectorstores/chroma";
import { OpenAIEmbeddings } from "@langchain/openai";

// Step 1-2: Embed and store documents
const vectorStore = await Chroma.fromDocuments(
  [
    { pageContent: "Node.js uses an event-driven architecture", metadata: { source: "docs" } },
    { pageContent: "Express.js is a minimal web framework for Node", metadata: { source: "docs" } },
    { pageContent: "React is a frontend JavaScript library", metadata: { source: "docs" } },
  ],
  new OpenAIEmbeddings()
);

// Step 3-5: Search by meaning
const results = await vectorStore.similaritySearch(
  "How does Node handle concurrent requests?", // query
  2  // return top 2 results
);

console.log(results[0].pageContent);
// "Node.js uses an event-driven architecture"  ← semantically similar!
```

## Cosine Similarity

The most common distance metric for embeddings. It measures the **angle** between two vectors, ignoring magnitude:

```javascript
function cosineSimilarity(a, b) {
  let dotProduct = 0;
  let normA = 0;
  let normB = 0;
  
  for (let i = 0; i < a.length; i++) {
    dotProduct += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  
  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
  // Returns: 1.0 = identical, 0.0 = unrelated, -1.0 = opposite
}
```

## Comparing Vector Databases

| Feature | Pinecone | ChromaDB | Weaviate | pgvector |
|---------|----------|----------|----------|----------|
| **Type** | Managed cloud | Open-source | Open-source | PostgreSQL extension |
| **Hosting** | Fully managed | Self-hosted / cloud | Self-hosted / cloud | Your existing Postgres |
| **Best For** | Production at scale | Prototyping, local dev | Hybrid search | Adding vectors to existing SQL |
| **Filtering** | Metadata filters | Metadata filters | GraphQL-like filters | SQL WHERE clauses |
| **Free Tier** | Yes (limited) | Unlimited (local) | Yes | Free (self-hosted) |
| **Latency** | ~50ms | ~10ms (local) | ~30ms | Depends on index |

### When to Use What

- **Prototyping / learning:** ChromaDB (runs locally, no API key needed)
- **Production SaaS:** Pinecone (zero ops, auto-scaling)
- **Already using Postgres:** pgvector (no new infra)
- **Need hybrid search:** Weaviate (combines vector + keyword search)

## Chunking Strategies

Before embedding documents, you need to split them into chunks. Chunk size directly impacts retrieval quality.

```javascript
import { RecursiveCharacterTextSplitter } from "langchain/text_splitter";

const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 1000,      // ~250 words per chunk
  chunkOverlap: 200,    // 20% overlap to preserve context at boundaries
  separators: ["\n\n", "\n", ". ", " "], // Split hierarchy
});

const chunks = await splitter.splitDocuments(documents);
```

> **Pro Tip:** Smaller chunks (500-1000 chars) improve retrieval precision but lose context. Larger chunks (2000-4000 chars) preserve context but reduce precision. The sweet spot depends on your use case.
