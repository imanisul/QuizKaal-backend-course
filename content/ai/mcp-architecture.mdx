## The Integration Nightmare

Before MCP, if you built an AI application and wanted it to read from Slack, GitHub, and a local Postgres database, you had to write custom API integrations for all three. If someone else built a different AI app, they had to write those exact same integrations again.

## What is MCP?

The **Model Context Protocol (MCP)** is an open standard introduced by Anthropic. It standardizes how AI models access external data and tools securely.

### The Architecture

MCP uses a Client-Server architecture:

1. **MCP Hosts:** The application the user interacts with (e.g., Claude Desktop, Cursor IDE).
2. **MCP Clients:** Protocol clients running inside the Host that maintain connections to servers.
3. **MCP Servers:** Lightweight programs that expose data and tools. They run locally or remotely.
4. **Local Resources:** The actual data (files, databases, APIs) the Server connects to.

```
┌──────────────┐          ┌──────────────┐          ┌──────────────┐
│  Claude App  │          │  MCP Server  │          │  Enterprise  │
│  (MCP Host)  │ ◄──────► │  (GitHub)    │ ◄──────► │  GitHub API  │
└──────────────┘   JSON   └──────────────┘          └──────────────┘
      │            RPC
      │
      ▼
┌──────────────┐          ┌──────────────┐          ┌──────────────┐
│  MCP Server  │ ◄──────► │  Postgres DB │          │  Local Files │
│  (Database)  │          │  (Local)     │          │              │
└──────────────┘          └──────────────┘          └──────────────┘
```

## The Three Capabilities of MCP

An MCP Server can expose three types of capabilities to the client:

### 1. Resources (Read-only data)
Resources are like files. The AI can read them to get context. They are identified by URIs (e.g., `file:///logs/app.log` or `postgres://schema/users`).

### 2. Prompts (Templates)
Pre-defined prompt templates that the server provides. The user can invoke them (e.g., "Review this code") and the server will fill in the template with dynamic data before sending it to the AI.

### 3. Tools (Executable actions)
Functions the AI can call to take action (e.g., `execute_query`, `create_github_issue`, `fetch_url`). This is how the AI interacts with the world.

## Security & Trust

Security is the primary reason MCP runs as a local server rather than having the AI cloud provider connect directly to your APIs:

- **Local Execution:** MCP servers run on *your* machine or *your* infrastructure.
- **No Inbound Ports:** The AI provider (like Anthropic) never connects to your database. Your local Claude app connects to your local database via the MCP server.
- **User Control:** The host application explicitly asks the user for permission before executing dangerous tools.

## Building an MCP Server

Building an MCP Server in Node.js/TypeScript using the official SDK is straightforward:

```typescript
import { Server } from "@modelcontextprotocol/sdk/server";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio";

// 1. Initialize Server
const server = new Server(
  { name: "weather-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

// 2. Define Tools
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "get_weather",
        description: "Get the current weather for a city",
        inputSchema: {
          type: "object",
          properties: {
            city: { type: "string" }
          },
          required: ["city"]
        }
      }
    ]
  };
});

// 3. Handle Tool Execution
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "get_weather") {
    const city = request.params.arguments.city;
    const weather = await fetchWeatherAPI(city); // Your logic here
    
    return {
      content: [{ type: "text", text: `Weather in ${city}: ${weather}` }]
    };
  }
  throw new Error("Tool not found");
});

// 4. Start the server (communicates via standard input/output)
const transport = new StdioServerTransport();
await server.connect(transport);
```
