## Chatbot vs Agent

A **chatbot** generates text in response to input. An **agent** can **reason, plan, use tools, and take actions** to accomplish a goal.

| Feature | Chatbot (GPT) | Agent |
|---------|--------------|-------|
| **Decides actions** | No — just generates text | Yes — chooses which tools to call |
| **Uses external tools** | No | Yes — APIs, databases, web search |
| **Plans multi-step tasks** | No | Yes — breaks goals into subtasks |
| **Reflects on errors** | No | Yes — retries with improved approach |
| **Has memory** | Only within context window | Persistent memory across sessions |

## The Four Pillars of Agentic AI

### 1. Planning

The agent breaks a complex goal into smaller, achievable steps.

```javascript
// User: "Research the top 3 competitors and create a comparison report"

// Agent's internal plan:
const plan = [
  "Search the web for the company's main competitors",
  "For each competitor, find their key features and pricing",
  "Compare features side by side",
  "Write a structured markdown report",
  "Save the report to a file"
];
```

### 2. Tool Use

The agent has access to tools (functions) it can call to interact with the real world.

```javascript
import { DynamicStructuredTool } from "@langchain/core/tools";
import { z } from "zod";

const searchTool = new DynamicStructuredTool({
  name: "web_search",
  description: "Search the web for current information",
  schema: z.object({
    query: z.string().describe("The search query"),
  }),
  func: async ({ query }) => {
    const results = await tavilySearch(query);
    return JSON.stringify(results);
  },
});

const calculatorTool = new DynamicStructuredTool({
  name: "calculator",
  description: "Perform mathematical calculations",
  schema: z.object({
    expression: z.string().describe("Math expression to evaluate"),
  }),
  func: async ({ expression }) => {
    return String(eval(expression)); // In production, use a safe evaluator
  },
});
```

### 3. Memory

Agents maintain context across interactions:

- **Short-term memory:** Current conversation (context window)
- **Long-term memory:** Persisted facts, preferences, past interactions (stored in a database)
- **Working memory:** Intermediate results during a multi-step task

### 4. Reflection

After taking an action, the agent evaluates the result and decides if it needs to try again.

```javascript
async function reflectiveAgent(goal) {
  let attempt = 0;
  let result = null;
  
  while (attempt < 3) {
    // Act
    result = await executeStep(goal);
    
    // Reflect
    const evaluation = await model.invoke(`
      Goal: ${goal}
      Result: ${result}
      
      Was this result satisfactory? If not, what should be done differently?
    `);
    
    if (evaluation.content.includes("satisfactory")) {
      return result;
    }
    
    // Improve and retry
    goal = evaluation.content; // Use the reflection as the new prompt
    attempt++;
  }
  
  return result;
}
```

## Agent Architectures

### ReAct (Reasoning + Acting)

The most popular pattern. The agent alternates between **thinking** (reasoning) and **acting** (calling tools).

```
Thought: I need to find the current stock price of Apple.
Action: web_search("Apple stock price today")
Observation: Apple (AAPL) is trading at $198.50
Thought: Now I need to calculate the market cap.
Action: calculator("198.50 * 15400000000")  
Observation: 3,056,900,000,000
Thought: I now have enough info to answer.
Final Answer: Apple's market cap is approximately $3.06 trillion.
```

### Plan-and-Execute

The agent creates a **full plan** upfront, then executes each step. Better for complex, multi-step tasks.

```javascript
// Step 1: Plan (using a planner LLM)
const plan = await plannerLLM.invoke(
  "Create a plan to analyze our website's SEO performance"
);
// Plan: 1. Crawl site  2. Check meta tags  3. Analyze page speed  4. Generate report

// Step 2: Execute each step with an executor agent
for (const step of plan.steps) {
  const result = await executorAgent.invoke(step);
  // Each step can use tools, make API calls, etc.
}
```

## When to Use Agents vs Chains

| Use Case | Chains | Agents |
|----------|--------|--------|
| **Fixed workflow** | ✅ Predictable, fast | Overkill |
| **Dynamic decisions** | Can't adapt | ✅ Chooses tools based on input |
| **Error recovery** | Fails on error | ✅ Retries with different approach |
| **Cost** | 1-3 LLM calls | 5-20+ LLM calls |
| **Latency** | 1-3 seconds | 10-60+ seconds |
| **Reliability** | High (deterministic) | Lower (non-deterministic) |

> **Rule of thumb:** Use chains when you know the exact steps in advance. Use agents when the steps depend on intermediate results or when the task requires dynamic decision-making.
